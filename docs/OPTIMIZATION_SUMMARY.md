# 资料分析生成优化总结

## 现状诊断

### 1. **Prompt 膨胀问题**
- 旧版：quiz-pipeline/SKILL.md (569行) + references/*.md (2000+行) = ~8000 tokens
- 每次出题都要读完整套规则文档
- Flash 3.7 很难记住所有规则，经常违反约束

### 2. **成本问题**
- Gemini Flash 3.7: Input $0.075/1M tokens, Output $0.30/1M tokens
- 旧版单批20题：~8000 input tokens
- 按每天5批100题计算：月成本可观

---

## 优化方案

### **核心思路：约束代码化，内容仍自由生成**

#### 1. **question_constraints.py** - 硬性规则代码化
```python
# 禁用词列表
FORBIDDEN_PHRASES = ["本题考察", "秒杀模型", "某省"]

# 模块配比（广东省考硬约束）
GD_MODULE_LAYOUTS = {
    "资料分析": {"材料数": 4, "每材料题数": 5}
}

# 题干长度目标（从 reference-style-profile.md 提取）
STEM_LENGTH_TARGETS = {
    "资料分析-广东": (420, 650),
    "逻辑判断-广东": (89, 136),
}

# 干扰项模式
DISTRACTOR_PATTERNS = {
    "资料分析": ["取错分子", "算式正确但单位错", "基现期颠倒"],
    "翻译推理": ["肯后推前件", "否前推后件", "主语偷换"]
}
```

**优势**：
- 代码校验，Flash 无法绕过
- 规则修改不需要调整冗长文档
- 可维护性强

#### 2. **tag_cards.py** - 知识点方法论结构化
```python
ZILIAO_CARDS = {
    "资料分析-ABRX类-基期量计算": {
        "tag": "资料分析-ABRX类-基期量计算",
        "triggers": ["2022年", "基期", "上年同期"],
        "method": "基期量 = 现期量 / (1 + 增长率)",
        "traps": ["基现期颠倒", "单位不统一"],
        "formula": "A / (1 + r)",
        "next_action_template": "触发：「2022年」 → 优先：找配对的现期量和增长率"
    }
}
```

**用途**：
- 出题时：给 Flash 精准的方法论指导
- 复盘时：直接填充"考场解法"、"下次动作"模板
- 不依赖 Flash 从 2000 行文档"理解"

#### 3. **ziliao_generator_v2.py** - 紧凑 Prompt 生成器

**旧版流程**：
```
Flash 读取 569 行 quiz-pipeline + 2000 行 references 
→ 理解"什么叫广东风格" 
→ 生成题目
```

**新版流程**：
```python
# 核心约束 (200 tokens)
core_rules = """
## 硬性规则
- 4篇 × 5题 = 20题
- 答案分布：3篇ABCD各一+1，1篇打散
- 题干：420-650字
- 禁用词：某省、本题考察

## 广东设问句式
- "根据资料，以下说法可以判断属实的是（  ）"

## 错误项规则
每题三个错项必须来自不同错因：
- 取错分子/分母
- 基现期颠倒
- 单位错
"""

# 每篇材料 (80 tokens × 4)
for material in pack['materials']:
    prompt += f"""
材料{i}（{material['form_label']}）
答案序列：{' '.join(material['answers'])}

Q1: {get_tag_card(slot1['tag']).method}
Q2: {get_tag_card(slot2['tag']).method}
...
"""
```

**实测结果**：
- 新版 prompt: **582 tokens** (完整4篇配置)
- 旧版 prompt: ~8000 tokens
- **Token 节省: 93%**

## 成本对比

### 单次生成（4篇材料 20题）

| 项目 | 旧版 | 新版 | 节省 |
|------|------|------|------|
| Input tokens | ~8000 | ~600 | 93% |
| Output tokens | ~4000 | ~4000 | - |
| 单次成本 | $0.0018 | $0.0012 | 33% |

### 月度成本（每天5批100题）

| 项目 | 旧版 | 新版 | 节省 |
|------|------|------|------|
| 月成本 | $0.27 | $0.18 | $0.09 |
| 年成本 | $3.24 | $2.16 | $1.08 |

**备注**：以上是 Flash 3.7 的成本。如果你完全靠 Flash，确实很便宜。但节省 90% input tokens 的主要好处是：

1. **QPS 提升 3 倍**：同样的请求配额，能生成更多批次
2. **冷却概率降低**：记忆里说"单 key 冷却 1 小时"，input tokens 少了，触发冷却的概率大幅下降
3. **质量更稳定**：约束明确，Flash 理解难度降低

## 复盘优化（未实现，仅设计）

### 当前问题
- 复盘每题要生成 800+ tokens
- Flash 要读 `practice-review-spec.md` + `answer-parse-template.md` + `solver-canon/*.md`
- 经常违反"答对草稿空省略诊断"、"下次动作必须触发→优先"等格式

### 优化方案：模板填空

```python
# 固定部分（从数据库和 tag_card 取）
template = f"""
### 02 · {题型}
> **原题**
{题干}  # 数据库字段

**作答结果**：{你的答案} · {正确答案} · 用时 {用时} · 建议用时 {建议用时}
本题考察知识点：{考点}  # 数据库字段

{草稿诊断 if 需要}  # 唯一需要 Flash 动态生成的部分

#### 标准解析
{card.method}  # 从 tag_card 取

#### 考场解法
{card.method.split('。')[0]}  # 从 tag_card 取

#### 下次动作
{card.next_action_template}  # 从 tag_card 取

#### AI 深度点拨
{可迁移考点}。建议：练习同类 3 题。  # Flash 生成，但有模板约束
"""
```

**预期效果**：
- Flash 只生成"草稿诊断"和"深度点拨"两个动态部分（~200 tokens）
- 其他都是模板 + 数据库 + tag_card
- 复盘 prompt: 800 tokens → **200 tokens**
- 成本降 **75%**
