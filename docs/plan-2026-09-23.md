## A. 让已有数据变得可执行

### A1. 知识债看板（优先级最高）

**现状**：`kaodian_debts` 表有 87 笔未清债，但 `src/` 里没有任何页面读它，
`mistakes` 表也只有后端在写。系统里最可执行的数据完全不可见。

**债务规则**（`scripts/kaodian_profile.py` 的 `apply_debt`，`DEBT_CLEAR = 2`）：
某考点错一次记一笔债；之后连续做对 2 次才算清偿；中途错一次，`recovery_streak` 归零重来。

**要做**：
- 新页面（或挂在「知识点」页下的一个页签），后端新增 `GET /api/kaodian/debts`。
- 列表按 `wrong_count × 距 last_wrong_at 的天数` 降序；每行显示考点名、累计错次、
  连对进度（`0/2`、`1/2`）、最近一次错的日期、当前掌握度与置信度。
- 每行一个「出这个考点的变式卷」按钮：调 `scripts/quiz_lite.py --module <模块>
  --tag <该考点> --count 5`，走现有的后台出题链路。
- 顶部一行汇总：未清 N 笔 / 本周清掉 M 笔。

**验收**：打开页面能看到 87 笔债并按紧急度排序；点按钮能出到对应考点的卷子；
某考点连对 2 次后该行自动消失（或进「已清偿」折叠区）。

### A2. 交卷后的复盘强提醒

**现状**：空题现在会自动入画像，但**有作答的题仍然只能靠 Hermes 复盘写证据**。
不复盘的那一场，画像只看得见空题——等于只记了坏消息。

**要做**：交卷结果页检测该场 `kaodian_events` 覆盖率（复用
`practice_coverage` 的口径，服务端已有 `review-complete` 的同款查询），
未满则显著提示「这场还有 N 道题的证据没写，去复盘」，并直接给「让 Hermes 复盘」按钮。
已有的 `onAnalyzeWithHermes` 就是入口，只需把提示做强。

**验收**：交完一份有错题的卷子且未复盘时，结果页有明确提示；复盘封存后提示消失。

### A3. 连对进度可视化

**现状**：`recovery_streak` 是系统里最像「进度条」的字段，但从未露出。

**要做**：在 A1 的看板和知识点页的考点卡片上，把 `0/2 → 1/2 → 已清偿` 画成进度点。
清偿时给一次明确的正反馈（这是清债过程里唯一的即时激励）。

**验收**：清掉一笔债时界面上看得见状态跳变。

### A4. 补全 learner_snapshot（让 Hermes 能给出策略建议）

**现状**：`scripts/learner_snapshot.py --compact` 给 Hermes 的快照里**没有
`recovery_streak` 和债务年龄**，所以它看不到「错 32 次、连对 0 次」这个模式，
只能反复说「低置信待测」。这不是模型能力问题，是数据没给到。

**要做**：在 compact 快照里增加一个「知识债」段落，最多列 6 笔，每笔给：
考点、累计错次、连对进度、距上次错多少天。并补一句口径说明：
「连对 2 次才算清偿；连对为 0 且错次高的，优先安排同考法变式卷，不要开新考点。」

**验收**：问 Hermes「现在该练什么」时，它能自己说出「先清这几笔债」，
而不是只给「低置信待测」。

### A5. 限时模式（可选，考场适配）

**现状**：练题不限时。#310 那场在一道题上耗了 460 秒，真考场这是三道题的时间。

**要做**：AI 练题开卷时可选「每题限时 N 秒」，超时自动跳到下一题并留空。
空题现在已经会按停留时长自动进画像，刚好接得上（超时留空 = 停留久 = 满权重证据）。

**验收**：开启限时后超时会自动跳题，且该题按空题写入证据。

## B. 复盘审核页签（AI 练题）

**目标**：讲过一遍不等于会了。隔几天重做同一套，用两次作答对照首次复盘的要求做验收。
后端的 `POST /api/practice/sessions/:id/audit` 和前端的审核场次渲染今晚已经上线，
缺的是「该审核哪一套」的入口。

### 入选条件（四个都满足）

1. 已交卷（`ended_at` 非空）
2. 已完成首次复盘并封存（`profile_reviewed_at` 非空）
3. 距封存 ≥ 2 天（太早重做是在考短期记忆，不是考掌握）
4. 没有正在进行的审核场（`audit_of_session_id = 该场 且 ended_at 为空`）

### 优先级公式

```
优先级 = 未掌握题数 × 遗忘系数 × 债务系数

未掌握题数 = 该场 kaodian_events 里 is_correct = 0 的条数（含自动写入的空题）
遗忘系数   = 距首次复盘的天数，按 21 天半衰期折算（与系统既有的回捞口径一致）
债务系数   = 该场涉及的未清知识债笔数（1 + 笔数，避免为 0）
```

### 界面

- AI 练题首页新增页签「复盘审核」，与现有的「默认 / 时间 / 模块」并列。
- 卡片文案：`首次 1/10 · 复盘于 3 天前 · 8 道未掌握 · 涉及 4 笔未清债`，
  右侧「开始审核」按钮直接调 `/audit`。
- 空态文案：「还没有到期的套题。首次复盘满 2 天后会出现在这里。」

### 审核完成后的归宿

- 全部判「有效掌握」→ 移出列表。
- 仍有「未掌握」→ 按新的未掌握数重新排队，等下一个周期再出现。

**验收**：页签能按优先级列出待审套题；点进去能按原题顺序重做；
交卷后 Hermes 走审核流程；判定有效掌握的套题不再出现。

## C. Hermes 行为边界

三件事：不许乱改代码、允许改知识点、不许工具空转卡死。
下面每项都标了改哪个文件。

### C1. 现状（都是关着的闸门）

```yaml
# ~/.hermes/config.yaml
approvals:
  mode: 'off'                    # 改任何文件都不需要确认
hooks: {}                        # 没有任何钩子
hooks_auto_accept: true
tool_loop_guardrails:
  hard_stop_enabled: false       # 工具死循环只警告，不停止
  hard_stop_after: {exact_failure: 5, same_tool_failure: 8, idempotent_no_progress: 5}
agent:
  max_turns: 90                  # 单轮最多 90 次工具往返
```

仓库里也**没有 `AGENTS.md`**，即没有任何仓库级的 Agent 行为约定。

### C2. 指哪打哪：写操作白名单

**原则**：默认只读；写操作按路径白名单放行，白名单之外一律需要确认。

**允许无条件写入**（这些是它的本职工作产物）：

```
data/practice-reviews/**      复盘报告
data/exam-reviews/**          录屏复盘报告
data/voice-notes/**           口述笔记
data/manual-*/**              出题中间产物
~/.hermes/memories/**         记忆与用户画像
hermes-skills/**              解法卡、skill 文档（教研内容，见 C3）
```

**禁止直接写入**（要改先说明、由人确认）：

```
src/**  server/**  scripts/**  package.json  vite.config.js  *.lock
```

**落地方式**（两层，建议都做）：

1. **仓库层**：新建 `AGENTS.md`，写明上述边界、以及「改代码前必须先说清改哪个文件、
   为什么、影响什么，等我确认」。这是 Hermes 读得到的行为约定。
2. **配置层**：`~/.hermes/agent-hooks/` 下加一个 pre-write 钩子脚本，
   对不在白名单的路径返回拒绝并提示走确认流程；把 `hooks_auto_accept` 改为 `false`。
   （目录已存在，当前为空。）

**验收**：让它改 `src/` 下任意文件时会被挡下并要求确认；写复盘报告和口述笔记畅通无阻。

### C3. 知识点权限：明确放行

**要求**：知识点的细分、改名、合并、删除，Hermes 应当有完整权限——这是教研工作，
不是改代码。

**允许的操作**：

```
python3 scripts/kaodian_profile.py --register / --record / --mastery / --recompute
python3 scripts/kaodian_taxonomy.py（词表校验与规范化）
写入 src/knowledge/fenbiTree.json 的别名段
写入 hermes-skills/gd-gongkao-coach/references/solver-canon/**（考点卡片）
写入 hermes-skills/**/knowledge-point-extension.md（新考点登记）
```

**边界条件**（写进 `AGENTS.md`）：
- 新增考点必须先 `--register` 登记，标签格式必须是 `模块-一级-二级`（科学推理走
  `科学推理-学科-考点`），不得在会话里临时另造同义标签。
- 删除或合并考点前，必须先说明影响到哪些历史证据（`kaodian_events` 里有多少条），
  并保留别名映射，不得让历史流水失去归属。
- 改动 `fenbiTree.json` 的叶子名时，必须同步检查
  `scripts/fenbi_taxonomy.py::tags_for_canon_lookup` 的反查是否还能命中
  solver-canon 里的旧主标签（今晚就踩过这个坑：叶子改名导致取到错误的解法卡）。

**验收**：它能独立完成一次考点细分（登记 + 改卡片 + 保留别名），
且改完后 `python3 scripts/test_quiz_generator.py` 仍然全过。

### C4. 工具空转与卡死

**现象**：聊天时经常无端调用工具、反复失败、最后卡住。

**三个抓手**：

1. `tool_loop_guardrails.hard_stop_enabled` 改为 `true`。
   现在是只警告不停止，所以它会一直撞墙撞到超时。建议同时收紧阈值：
   `exact_failure: 3`、`same_tool_failure: 4`、`idempotent_no_progress: 3`。
2. `agent.max_turns` 从 90 降到 30 左右。单轮 90 次工具往返，正常任务用不到，
   出问题时却足够它空转十几分钟。
3. 在 `AGENTS.md` 里写死一条：**闲聊和策略讨论不要调用任何工具**；
   需要数据时只允许 `learner_snapshot.py --compact` 这一条命令；
   同一个工具连续失败 2 次就停下来说明情况，不要换着花样重试。

**验收**：随便聊天时不再触发工具调用；工具连续失败时会主动停下来报告，
而不是一直转到超时。

### C5. 附带修复：截断与压缩（今晚讨论过，未做）

- 回答被截断（`finish_reason=length`）或上游报错时，界面要明示，
  并给一个「继续写完」按钮（走一次带「不要重述前文」的续写）。
  今晚出过一次：模型撞上输出上限，续写请求又被上游 EOF 三次，
  整轮 `status=error` 收尾，但界面上什么都没显示。
- 上下文过重时给一个手动「压缩上下文」按钮，走网关的 `session.compress`。

## D. 使用方式（不是开发项，是配套习惯）

1. **一个会话只干一件事**：排计划 / 出题 / 复盘 / 审核，各开各的，做完就换。
   会话历史不是资产，资产在 `kaodian_profile` 和复盘报告里。
2. **交卷后立刻复盘**。不复盘那一场只有空题进画像，等于只记了坏消息。
3. **现阶段先清债、不开新点**。87 笔未清、top5 连对为 0，说明广度够了深度不够。
4. **隔 2-3 天做复盘审核**，把「低置信」变成「高置信」最快的路。
5. **口述留给讲不清楚的东西**（卡在哪、怎么想的、状态如何），
   指令类的直接打字，更快也不占上下文。
6. **别信它张口说的掌握度**，让它跑快照，或者自己看知识点页。
