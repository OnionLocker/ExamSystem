# 网页知识点内容维护（Hermes 定点入口）

用户逐个讨论知识点。只有明确要求新增、扩展、修改、改名、移动、删除内容时才写入；概念交流直接回答。

学习状态和网页上的知识债是另一条记录：Hermes 只负责围绕用户当前指定的知识点交流或修改内容，不代替用户点击学习状态。用户确认“我已学过”后，之后的新错题才算知识债；旧记录保留作历史证据。

## 最短操作路径

在 `/home/ubuntu/ExamSystem` 运行：

```bash
# 用户已指定完整三级标签，不要先搜索全库
node scripts/knowledge-content.mjs outline '数量关系-数学运算-概率问题'
# 只读目标正文，返回 revision 与 node
node scripts/knowledge-content.mjs get '数量关系-数学运算-概率问题' equal-groups
# 将补丁写入 /tmp/knowledge-patch.json 后提交，保存即生效，无需 build
node scripts/knowledge-content.mjs apply '数量关系-数学运算-概率问题' /tmp/knowledge-patch.json
```

只知道名称时：`node scripts/knowledge-content.mjs find '概率'`。`catalog` 和 `outline` 只认完整三级标签，传“容斥原理”“数学运算”这类简称会返回空列表；这时改用 `find`，不要转去查 exam.db。

用户要给知识点配图：先在聊天里画给用户看（`../diagram-drawing.md`），用户明确要求保存后，再把图片 Markdown 写进正文。已有 `-@equal-groups` 形式的定位时，`@` 前是三级标签，后是稳定节点 ID；可以直接 get，无需 outline。

`outline` 只给目录；`get 标签 节点ID` 只给该页。首次确实需要重组整个知识点时才用 `get 标签`。不要读取其他知识点或学习数据库。

**节点 ID 不能代替完整三级标签。** 即使已知 ID，也要用 `get '言语理解与表达-逻辑填空-混搭填空' 节点ID`，不能用 `get 节点ID`；`apply` 同样先传父级完整三级标签，节点 ID 放在补丁的 `id` 字段中。

### 多页重组也走短路径

用户已经明确结构并同意修改时：一次 `get 标签` 读取整份文档 → 集中准备补丁 → 一次 terminal 串行执行已有 `apply` → 一次 `get 标签` 核对标题、父节点和正文。无需为了改内容再探查源码、UI、数据库实现或反复 outline；保存已实时生效。各次 apply 使用上一次返回的 revision，出错即停，不让后续命令掩盖失败。

含公式的正文先写 UTF-8 文件，或用带引号的 heredoc `python3 <<'PY'` 编排；Python 通过 `subprocess.run([...], input=json.dumps(patch, ensure_ascii=False), text=True, check=True)` 将补丁传给 `apply 标签 -`。**不要用双引号包裹的 `python3 -c "…"` 或 shell echo 承载正文**：其中的 `$$`、`$k`、`$(AB)` 会被 shell 展开并损坏公式。最后读回一次确认公式仍是原文，再报告完成。正常流程通常只需读取、写入、核验几次模型往返，不为每个节点单独开启一轮。

## 从当前节点出题

```bash
# 可省略标签查看全目录；指定知识点时只查该父级
node scripts/knowledge-content.mjs catalog '数量关系-数学运算-工程问题'
# 只点模块或二级范围时按前缀查询，不需要读取全目录
node scripts/knowledge-content.mjs catalog '判断推理-逻辑判断'
# 先看实际子点配额；此命令不生成、不登记、不入库
python3 scripts/quiz_lite.py --module '数量关系' --tag '数量关系-数学运算-工程问题' \
  --count 6 --difficulty mid --batch-id 'YYYYMMDD_hermes_工程_01' --plan-only
```

可训练子点的 summary/markdown 必须写全自身的识别信号、适用条件、解题动作和排除边界；出题只使用所选节点的定义，不隐式拼接祖先整张讲解卡，避免共享参考卡重新带入旁系考法。

数量讲解卡保存前做数学自检：每个新公式写清适用条件，用一个完整数值例核算；对“只能／不能／必须／总是”等绝对断言尝试反例。找不到充分依据就写成有条件的方法建议，不能把常用技巧写成数学禁令。例如工程题总量可取任意一致单位，单独或合作完工时间都可用于合理赋值；合作工期 12、15、20 天可赋总量 60，不能写“只有单独工期才能取公倍数”。这属于当前卡片的局部内容核验，不额外出卷、不写学习证据。

言语讲解卡保存前核对每组辨析例词：共享汉字不等于近义词，拆字不能替代词语整体含义；程度轻重必须比较同一语义维度，不能把范围、重要性、强弱、大小等不同维度排成程度阶梯。常见搭配和典型对象不能一概写成排他禁令，题材也不限于公文政论。例子拿不准时删去该例或换成含义明确的常见例子，不用生僻措辞填补。子点列出的辨析维度是训练范围，不要求每题、每个错项逐一完成全部动作；拆语素是可选理解手段，中性词可以用于批评语境。以完整语境和通常词义为准，不能为了套教法编造排他规则。

实际生成去掉 `--plan-only` 后按 quiz-pipeline 后台执行。父级目标自动分配当前启用的末级子点，用户指定一个子点时使用 catalog 的精确显示名或稳定 `tag`（三级标签-@节点ID；outline 中为 `linkTag`），不手拼历史超长标签。用户要求各子点数量、easy/mid/hard 比例时使用 `--blueprint` 显式编排。

例如工程问题目前只有一个粗分子点，之后通过 apply 在它下面拆出三个子点，下一次父级出题自动覆盖这三个末级；点名其中一个则只针对该点。改名保持 ID，停用后不再进入新批次。正式生成前脚本会登记所选稳定叶子的当前定义并冻结内容版本，供出题和审核共用；增加讲解页或查询目录本身不写作答证据，也不改变已学状态。

## 补丁格式

```json
{
  "revision": 0,
  "op": "update",
  "id": "equal-groups",
  "markdown": "## 识别信号\n\n各组容量相同。\n\n## 核心公式\n\n$$\nP=\\frac{k-1}{N-1}\n$$\n\n## 例题\n\n10 人均分两组，甲乙同组的概率为 $4/9$。\n\n## 易错提醒\n\n甲已占一个位置，分子分母都减 1。"
}
```

**例子中的 revision 必须替换成刚读取的值。** 标准 JSON 中反斜线写成 `\\`；可用 Python `json.dump` 生成补丁，避免 shell 吃掉 `$` 或反斜线。Markdown 文件本身正常写单个反斜线。

- `create`：提供新的稳定英文小写 `id`、现有 `parentId`、`title`，可附 `summary`、`markdown`、`order`。例如在 `grouping` 下新增 `conditional-grouping`，不挂在总览的同级。ID 不是学习标签，不需要登记画像。
- `update`：只提交本次更改的字段。可更新 `title`、`summary`、`markdown`、`parentId`、`order`。正文是该页完整 Markdown，先 get 后保留未改段落。
- `archive`：只传 revision/op/id，停用这个内容节点及其下级的展示；数据保留，可以 `restore`。先说明网页哪些子页会一起隐藏。**历史作答影响为 0，因为接口根本不访问 exam.db。**
- `restore`：恢复节点；祖先若停用，需先逐层恢复祖先。
- 内容合并：先读取两个目标，将需保留的正文更新到接收页，再 archive 被合并页，每一步使用最新 revision。保留稳定链接与历史版本，不合并画像标签。

输出包含 `changed.id`、`revision`、`changed.linkTag` 和 `evidenceChanged:false`。完成后只简短告诉用户改了哪页、放在哪个父页，并给出 `本题考察知识点：<changed.linkTag>` 供网页跳转。不要声称运行了构建。

409 表示版本冲突：不要覆盖，不重复提交旧补丁。重新读取指定节点，只合并本次意图后用新 revision 提交。同一工具连续失败两次即停下说明，遵守 AGENTS.md。

## 排版规则

- 总览只写模型选择、边界与子考法入口，不塞全部子页正文。
- 方法页讲识别与共性；具体变式挂在方法节点下。
- 每页优先采用：`## 识别信号` → `## 核心公式` → `## 例题` → `## 易错提醒`。
- **重要公式单独成行**：核心模型、定义式、要背的结论公式一律写成独立的 `$$…$$`，**前后各空一行**（没有空行会被当成行内公式，失去公式底）。在列表项里时，公式行缩进到和列表文字对齐：

  ```markdown
  - 预留临界工作量：

    $$W_{\text{安全}} = W - P_{\text{正}}$$

  ```

  例题里的代入、联立、计算步骤可以留在行内 `$…$`。中文说明留在公式外，公式中的中文用 `\text{}`。
- **禁止用代码块画字符图**（`┌──`、`│`、`──>` 这类方框线）。题型分类、决策分支用 `tree` 模板画成图片（见 `../diagram-drawing.md` 的“分类决策树”），集合、线段、几何等结构用对应模板；图片 Markdown 单独成段。
- 一段只解释一件事；例题把条件、代入、答案分开。不要把长篇中文整段套进数学环境。
- title 简短，不加序号；summary 一句话；先说明公式成立的条件。

## 权限和存储

这是**网页教学内容**接口，只写 `data/knowledge-content.db`，保留每次修改前的版本。内容操作本身不会修改题库、事件、掌握度、画像标签、系统代码或配置；SQL、文件路径和 shell 命令都不是可写字段。不要直接编辑这个数据库。`probability.json` 是初始样例，运行中的修改走 CLI，不能靠改样例覆盖运行数据。实际出题时才由生成脚本另行登记所选稳定节点定义，不迁移既有历史证据。

所有已有三级知识点均可维护。新增真正独立的画像标签、合并或删除画像仍按 `knowledge-point-extension.md` 和 AGENTS.md 的证据数量、登记与别名规则办理。显示标题和层级调整不等于改名或合并画像。

系统代码、依赖、构建和部署不属于本接口权限，禁止为知识点内容操作修改 src/server/scripts 或运行 npm build。工具限制不代表整个 Hermes 进程已经处于操作系统沙箱。
