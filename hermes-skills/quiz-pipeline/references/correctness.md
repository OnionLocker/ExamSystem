# 正确性闸门细则

三条路线。目标只有一个：**恰好一个选项成立**，不多不少。

用户踩过的三种病都是这个数字不对：0 个成立（条件不足）、3 个成立（链条通太多）、
1 个成立但不是标注的那个（出题者翻译反了）。

---

## A 路：交叉形式化 + 机械判定

适用：翻译推理、推理形式、真假话、集合推理。

这条路是**决定性**的，跟模型强弱无关，所以能走就必须走。

### 为什么要「交叉」

判定器只保证「给定公式的判定不会错」，它**发现不了你把中文翻译反了**。
翻译反了照样能得出一个 `ok`，然后错题照样发给用户（这正是 07-30 题 5 的病）。另一种废题是 `P ⇒ P`：正确项只是复述已知实例，判定器也会先报 `ok`；现已改成 `echo_given_fact`，同样不算通过。

所以要两份独立的形式化：你的，和一个独立 agent 的。
两份分别跑判定器，结论必须一致。不一致说明中文有歧义、或者有人翻译错了。

### 步骤

**A1. 你自己形式化一遍**，写成 JSON：

```json
[
  {
    "id": "Q001",
    "premises": ["面试 -> 笔试", "面试 -> 录用"],
    "options": {
      "A": "!录用 -> !笔试",
      "B": "笔试 -> 录用",
      "C": "!面试 -> !笔试",
      "D": "录用 -> 面试"
    },
    "claimed_answer": "D"
  }
]
```

语法：`!`非　`&`与　`|`或　`->`蕴含（右结合）　`<->`等价　`()`分组。
变元不用声明，中文变量名直接写。

**A2. 跑判定器**：

```bash
python3 /home/ubuntu/ExamSystem/scripts/verify-logic.py draft-logic.json
```

**A3. 派一个独立 agent 独立形式化**。`delegate_task` 的 goal 用这个模板：

```
把下面这道逻辑题形式化成命题公式，只做翻译，不要做推理，不要判断哪个选项对。

语法：! 非，& 与，| 或，-> 蕴含，<-> 等价，() 分组。变元用中文短词。

常见句式对照：
- 如果 A 那么 B / 只要 A 就 B / 所有 A 都 B / A 就 B  =>  A -> B
- 只有 A 才 B  =>  B -> A
- 除非 A 否则 B  =>  !A -> B
- 除非 A 才 B  =>  B -> A
- 除非 A 否则不 B  =>  B -> A
- 不 A 就不 B  =>  B -> A
- A 是 B 的前提 / 基础 / 关键 / 必要条件 / 必经之路  =>  B -> A
- 为了 A 必须 B / A 离不开 B  =>  A -> B

高阶/复合命题常见形式化对照（Z3/verify-logic.py）：
- 假言联言否后：`(A & B) -> C` 且 `!C`  =>  推导出 `!A | !B`（等价于 `A -> !B` 或 `B -> !A`）
- 选言否定肯定：`A -> (B | C)` 且 `B -> D` 且 `A` 且 `!D`  =>  由 `!D` 得 `!B`，由 `A` 得 `B | C`，否一得 `C`
- 连锁否否逆否：`!D -> !C`（即 `C -> D`）且 `!A -> C` 且 `!D`  =>  由 `!D` 得 `!C`，由 `!C` 逆否得 `!(!A)` 即 `A`
- 肯后陷阱防范：`(A | B) -> C` 且 `D -> C` 且 `E -> D` 且 `E`  =>  有效肯前推得 `D` 与 `C`；对 `(A | B) -> C` 而言 `C` 为肯后，不可推导 `A` 或 `B`

只输出一个 JSON，不要任何解释：
{"premises": [...], "options": {"A": "...", "B": "...", "C": "...", "D": "..."}}

题干：
<题干原文>
选项：
A. <原文>
B. <原文>
C. <原文>
D. <原文>
```

注意这个 goal 里**不能出现** claimed_answer，也不能出现「验证一下我翻译得对不对」
之类的话——它只做翻译，不知道你的答案。

**A4. 用它给的公式再跑一次判定器**，然后比对两次结果：

| 比对结果 | 结论 |
|---|---|
| 两次都 `ok`，且唯一正确项相同 | 正确性通过 |
| 两次都 `ok` 但正确项不同 | **打回**。题干有歧义，两种读法得出不同答案 |
| 一次 `ok` 一次不是 | **打回**。至少有一份翻译错了，逐条对比两份公式找出分歧的那条 |
| 两次都不是 `ok` | **打回**。按下面的 verdict 表修 |
| 任一次 `echo_given_fact` | **打回**。正确项只是复述已知实例，零步推理，真题不会这样出 |

### 防范“肯后断链”与文本/公式脱节

1. **防范“肯后断链”废题（关键逻辑校验点）**：
   - 当前提链为 `A -> B -> C` 时，若已知事实给出了尾端肯定条件 `C`（肯后），无法向前推出 `A` 或 `B`（肯定后件推不出任何必然结论）。这会导致四个选项均推不出（0 个选项成立的废题）。
   - 形式化时必须用严格蕴含 `->`，绝不能错写成双向等价 `<->`（会导致判定器误判为可反向双向推导）。
   - 题干已知事实必须是**有效肯前**（如给 `A` 顺推）或**有效否后**（如给 `!C` 逆否倒推），确保逻辑链条能通畅传导至选项。
   - 变元名称必须在前提和选项中完全一致（如不能前提写“专项津贴”而选项写“获得专项津贴”），防止变元不一致导致机械判定报假 `no_answer` 或假 `ok`。

2. **绝对禁止在对话中暴露验证或使用 LaTeX 语法**：
   - 出题时验证过程、中途状态和正确答案必须完全静默（后台运行）。
   - 题目与解析中严禁出现 LaTeX 格式（如 `$\rightarrow$`），必须统一使用纯文本 Unicode 符号（`->`、`→`、`!`、`且`、`或`）。

### verdict 怎么处理

| verdict | 含义 | 你要做什么 |
|---|---|---|
| `ok` | 恰好一个选项能被必然推出，且与标注答案一致，并且不是已知回声 | 进下一步 |
| `echo_given_fact` | 唯一正确项只被「已知」实例蕴涵，没有走假言/选言规则 | 整题重写：正确项必须经过逆否、选言否定肯定或连锁 |
| `bad_formalization` | **公式本身有问题，判定结果不可信** | 看 `lint` 字段修**公式**，不要动题目 |
| `no_answer` | 没有任何选项能推出，题干条件不足 | 补前提（通常是缺一条链），重验 |
| `multiple_answers` | 多个选项都能推出 | 改写多余的那些，让它们推不出，重验 |
| `wrong_answer_key` | 唯一正确项不是你标的那个 | 改答案，并回查你哪一步翻译反了 |
| `contradictory_premises` | 题干前提自相矛盾 | 整题重写 |
| `bad_input` | 公式语法写错了 | 看 reason 修 |

### `bad_formalization` 要特别小心

这个 verdict 说的是**你的公式写错了**，不是题目有问题。
两种情况会触发，都会让判定器给出看似正常、实则无意义的结论：

- **整句没形式化**：中文变元之间忘了留空格，「除非甲否则乙」被当成一个变元名。
  判定器会报 `no_answer`，你如果照着去补前提，就是在修一道本来没病的题。
- **变元名笔误 / 描述不一致与反义变元分裂**：「录用」打成「綠用」，或前提写「专项津贴」而选项写「获得专项津贴」。判定器把它们当成两个无关命题，导致逻辑断链（报 `no_answer`）或得到假的 `ok`——必须保证前提和选项中的变元字符串完全一致；若题干包含反向概念（如“按期交付”与“延期交付”），统一使用否定符号 `!`（如 `按期交付` 与 `!按期交付`），避免引入新的独立的原子变元名导致形式化断链。

看到它就去改 JSON 里的公式，改完重跑。**不要改题干，不要改答案。**

`no_answer` 和 `multiple_answers` 的输出里带 `counterexample`，
那是「前提成立但该选项为假」的具体赋值，是现成的解析素材。

### 形式化的自查

形式化完、跑判定器之前，先回读一遍公式，逐条问自己：
这个公式说的和中文是一个意思吗？特别注意：

- 「只有…才…」和「如果…就…」方向相反，这是最高频的翻译错误
- 「除非 A 否则 B」是 `!A -> B`，「除非 A 才 B」是 `B -> A`，两者不同
- 「不 A 就不 B」不要写成 `!A -> !B` 然后忘了它等价于 `B -> A`（写哪个都行，但别写反）

## B 路：代码验算

适用：数量关系、资料分析。

在 `execute_code` 里把题算一遍，**四件事都要做**：

1. 算出正确答案的数值
2. 对每个干扰项，确认它的数值 **不等于** 正确值
3. 资料分析：材料里用到的每个数字都**抄进代码**，不许凭记忆
4. 涉及「约等于」「保留一位小数」「选最接近的」时，确认干扰项不会在容差内撞车
5. 资料分析若有表/图：必须用 `scripts/render_ziliao_figure.py` 生成 PNG，
   **禁止** `generate-question-image.py` / Gemini Banana 画表格或坐标轴。
   渲染用的数字必须与验算代码、材料文字为同一份原始数据。
   草稿须标明 paper_style=gd|gk|sz，篇幅对照 ziliao-paper-styles.md。

只算出正确答案就发题等于没验——**干扰项数值撞车是数量题最常见的废题原因**。

另外要确认题目有唯一解：方程组不能欠定，行程/工程问题不能出现负数解或非整数人数
这类物理上不成立的情况。

## C 路：双人独立盲审

适用：言语理解与表达、常识判断。这两类无法形式化，只能靠独立复核。

用 `delegate_task` 一次开 **2 个** 并行审查者（`tasks` 数组两项，
并发上限默认 3，两个安全）。

### payload 规则

**只给**：题干、选项。
**绝对不给**：`answer`、`explanation`、你的倾向、「我觉得是 D」之类任何暗示。

### 审查者 goal 模板

```
你是公考题目质检员。下面是一道尚未定稿的题，答案未知。

独立完成三件事，不要猜出题人想要什么答案：
1. 逐个选项表态：【成立 / 不成立 / 无法判断】，各写一句理由。
2. 给出你认为唯一正确的选项。
3. 明确回答：除了你选的那个，是否还有别的选项也站得住？有就指出是哪个。

最后一行只输出这个格式，便于机器读取：
VERDICT: <选项字母> | ALSO_VALID: <选项字母，逗号分隔，没有就写 NONE>

题目：
<题干>
选项：
A. ...
B. ...
C. ...
D. ...
```

常识判断额外要求：审查者必须联网核实事实性表述，不许凭印象。
涉及法条、数据、时间的，要求给出出处。

### 裁决规则

| 两名审查者的结果 | 结论 |
|---|---|
| VERDICT 相同，两边 ALSO_VALID 都是 NONE | 正确性通过 |
| VERDICT 相同，但有一边报了 ALSO_VALID | **打回**，改那个干扰项 |
| VERDICT 不同 | **打回**。这道题有歧义 |

VERDICT 不同时**不许取多数、不许自己拍板**。两个独立审查者选不出同一个答案，
说明题目本身不够干净——真题不会这样，用户在考场上也会被坑。

### 这条路的已知局限

审查者和你用同一个模型，盲区是一致的，所以它抓不出「你和它都看不出来」的错。
这是概率性手段的固有局限，也是为什么能走 A/B 路就绝不走这条路。
言语题尤其要压低出题量，宁可从 `batches/quizsim-pilot-100` 那类现成真题库里抽。
