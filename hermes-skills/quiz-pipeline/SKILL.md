# 出题流水线：动态考点与统一审核

本 skill 由 Hermes 和 DSH 共用同一份文件。只认意图；闸门、入库永远由脚本完成。

## 一套流程，平台只决定谁写题

选点与配额、考法变式分配（`--plan-only` 同一结果）、按题型切片的命题规则、逻辑演绎题形式化判定（`logic_model.py`）、补题只重出不合格的题、难度口径、命名、闸门、入库，Hermes 与 DSH 完全相同。区别只在写题和审核由谁的模型完成：

| | Hermes | DSH |
|---|---|---|
| 谁写题、谁审 | `quiz_lite.py` 调服务器模型（`model_router` 配置）写题，脚本内盲解官+考官审核 | DSH 自己写题，派子 agent 做盲解官 / 考官（逻辑非演绎题加独立核查官） |
| 当前 agent 做什么 | 抽参 → 一条后台命令 → 简报（本文第 2 步起） | 抽参 → `--plan-only` → 写题 → `--dsh-claims` → 派审 → `--dsh-check` → `--dsh-import` → 简报（先读 `references/agent-mode.md`） |
| 后台执行 | `terminal({command, workdir, background: true, notify_on_complete: true})`，等完成通知 | `pwsh({description, command, workdir, run_in_background: true})`，完成后用 `job_output` 读回执 |
| batch_id 前缀 | `YYYYMMDD_hermes_<考点>_<两位序号>` | `YYYYMMDD_dsh_<考点>_<两位序号>` |

写题方由平台固定，不因用户说“你自己出”“用服务器模型”而切换。图推（程序出图）、资料分析、申论两边都直接调用各自专用脚本：资料分析整套 `ziliao_agent_paper.py`、单篇/专项 `ziliao_material_pipeline.py`，由脚本内分角色的模型请求写材料与题、程序排选项、篇内审核后入库；DSH 不自己写资料题，也不走 `--dsh-import`。

下文命令示例按 Hermes 的 `terminal` 写法给出；DSH 改成 `pwsh` 写法，参数含义不变。

## 铁律

1. **不要绕过流程出题。** Hermes 不自己写题、不 `write_file` `questions.json`、不翻仓库找生成器。DSH 写的题必须经子 agent 审核、`--dsh-check` 预检、`--dsh-import` 闸门入库，不得省略审核或绕过脚本入库。
2. **脚本不存在或失败，就报失败。** Hermes 不回退到自己写题，DSH 不改用服务器模型；禁止手跑闸门，禁止用旧 runner 冒充成功。
3. **对话里不要打印题干、选项、答案。** 成功只报批次名和题量。
4. **出题要几分钟，必须后台跑。** Hermes 前台 terminal 只有 180 秒；后台写法见「平台差异」。
5. **录音请直接听，不要先转写再当用户正文。** 录音说根据快照选定考点并出 N 道，就出那个考点、那个题量。失败报原文，不要翻仓库。
6. **出题 agent 绝不改代码。** 两个平台都只做出题本职（DSH 写题步骤见 `references/agent-mode.md`），不自己写脚本切分解析原句、不手拼 `claim_index`、失败重导沿用原 batch_id。命中流程缺口时，**禁止**就地编辑 `scripts/**`、`server/**`、`src/**` 等任何代码，禁止为过闸门手改证据结构/手填对齐格式。按第 4 节兜底跑完当前批，并把缺口按 `references/dsh-generality-gaps.md` 的 backlog 格式登记，交由维护轨落地。

## 批次命名与推进节奏（用户长期要求）

- 题组名必须与当前知识目录一致：`广东省考行测-{模块}-{父知识点}-{难度}-{YYYYMMDD}`；指定子考法时在父知识点后、难度前追加该子点当前全名。难度显示“简单／中等／困难／综合”之一：easy/mid/hard 对应前三档，多档混合或 auto 为“综合”，不承诺各档配额。文字专项显式给唯一批次号，重复会被拒；资料入口可自动分配唯一编号。
- **单考法闭环打穿**：一个大考点下的细分考法要连续集中练透再推下一个。同构变式卷 100% 锁在同一考法内，变情境与陷阱，不变底层解题动作，严禁跨考法发散。
- 训练量与难度按当前失分动作和 `exam-sprint-plan.md` 调整。日常数量练习默认少量 auto 验证，不自动为每个子考法连出 mid/hard 两套；只有用户明确指定档位或难度配额时才设置 easy/mid/hard。
- 支持数量文字题、言语专项、判断中的纯文字逻辑题、资料文字题与确定性图表题。言语已有题型匹配和重复套路检查，可以按需求生成。
- 政治理论（判断/单选/多选）、常识应用（系统模块名“常识判断”，单选）已接入原文核验出题；具体操作见下文。用户点名模块或知识点就按需生成，不要求先完成固定课程。
- 图形推理有 12 种题型由程序出图（见下文「2c. 程序出图题」），其余图推细分、科学推理仍不能 AI 出题，使用粉笔/外采真题。不要用视觉模型画图或判图，旧的实验图题仍不能入库。

## 三步

### 1. 抽出参数

- 模块：政治理论 / 常识判断 / 判断推理 / 数量关系 / 言语理解与表达 / 资料分析（文字专项）
- 考点 `--tag`：用户或录音点名父知识点则写成粉笔 `模块-一级-二级`，脚本按当前网页内容树的启用末级子点自动分配，不要求用户报子点清单。
  - 平均数问题 → `数量关系-数学运算-平均数问题`
  - 工程问题 → `数量关系-数学运算-工程问题`
  - 排列组合 → `数量关系-数学运算-排列组合问题`
  - 翻译推理 → `判断推理-逻辑判断-翻译推理`
  - 中心理解题 → `言语理解与表达-片段阅读-中心理解题`
- 用户只点模块或“片段阅读”等上层范围时，运行 `catalog '判断推理'` 或 `catalog '言语理解与表达-片段阅读'` 等对应范围查询，在返回范围内按要求选当前知识点组成 blueprint，不能擅自缩成其中一个三级点。
- 要更细的考法，先 `node scripts/knowledge-content.mjs catalog '<完整三级标签>'`，使用当前精确显示名或返回的稳定 `tag`（三级标签-@节点ID；outline 中为 `linkTag`）。不要把网页子点手拼成历史 L4 名称。脚本在正式生成前自动登记所选稳定叶子定义，出题和审核共享本批快照。
- 题量：用户说几道就几道；点名考点没说数量则 **5**；不要擅自出 10 题或成套 20 题
- 数量难度：“广东省考难度”“贴近真题”“稍难一点”“多点基础题”都保留 **auto**，不翻译成全 mid/hard。用 blueprint 槽位的 brief 保留原话，并注明“命题倾向，非硬性难度门槛”；只有用户明确指定档位或配额（如“全部中等”“三道困难题”）才设置 easy/mid/hard。示例槽位：`{"tag":"<当前目录目标>","count":10,"difficulty":"auto","brief":"贴近广东省考真题，难度为命题倾向，非硬性难度门槛"}`。难度评为 easy 不等于题目不合格，答案正确性与考点检查保持严格。

粉笔 L3 是父级浏览与默认出题单位。当前网页目录决定子点的数量、名称、层级和启用状态；新增、拆分、改名、停用后新批次立即按最新目录解析。父级已拆分则均衡覆盖其当前末级；精确子点只覆盖该子树。题量小于叶子数时只抽部分，不声称全覆盖。旧的超长标签只兼容历史数据，不用它们代替当前目录。

题组显示名由生成脚本按目录统一生成：`广东省考行测-模块-父知识点-难度-日期`；点名子考法则为 `广东省考行测-模块-父知识点-子考法当前名称-难度-日期`。不自行简写知识点；“综合”只作独立难度段，不粘到知识点名称，不显示“自主难度”或英文档位；加入当天计划也不能覆盖题组名。

| 考法 | 识别信号 | 主标签 |
|---|---|---|
| 最值 | 和定排大小、抽屉、反向构造 | `数量关系-数学运算-最值问题` |
| 函数最值 | 二次函数、均值定理、乘积极值 | `数量关系-数学运算-经济利润问题` |
| 排列组合 | 加乘原理、捆绑插空、隔板分堆、错位圆桌 | `数量关系-数学运算-排列组合问题` |
| 概率 | 古典概型、伯努利、赛制决胜 | `数量关系-数学运算-概率问题` |
- **针对性出题与同构变式铁律**：出同构变式卷时，严禁考法发散！变的是业务情境与数值陷阱，不变的是底层解题动作。严禁在同构变式卷中掺入无关或偏门考法（如定位法卷子严禁出成赛制或独立关卡）。
- **批次规范命名**：显示名称由脚本按本批请求范围生成；父级配额卷写父级全名，精确子点在父级后追加当前子点全名，不把父级卷命名为首个子点。不要手写 source 覆盖脚本结果。
- `batch_id`：前缀按平台（见「平台差异」），`YYYYMMDD_<hermes|dsh>_<考点或模块>_<两位序号>`。新出一批用新序号，不得复用已入库批次；DSH 同一批失败重导沿用原 batch_id

资料分析共享材料或图表题使用下文专用入口。资料分析每日整套由定时任务自动出（见 2a-plus）；其余模块的每日自动成套生成目前暂停，按用户当前目标按需出题。

### 2. 考点和要求确认后，后台调用

DSH 从这里转去读 `references/agent-mode.md` 按其步骤走；下面的命令和 2a 节是 Hermes 的调用方式（选点、配额、变式与 DSH 的 `--plan-only` 结果一致）。

用户还在讨论知识点拆分时先讨论，不抢先出题。用户明确要求保存拆分时，通过 `knowledge-content.mjs apply` 保存节点及识别、解题动作和边界，再查询 catalog。正式生成前脚本登记当前所选稳定叶子定义，无需 Hermes 手动复制网页子点为另一套标签。仅查看或 `--plan-only` 不登记、不生成、不入库。

```
terminal({
  command: "python3 /home/ubuntu/ExamSystem/scripts/quiz_lite.py --module '数量关系' --tag '数量关系-数学运算-排列组合问题' --count 5 --batch-id 'YYYYMMDD_hermes_排列组合_01'",
  workdir: "/home/ubuntu/ExamSystem",
  background: true,
  notify_on_complete: true
})
```

等 JSON。成功：`status=success`，直接使用回执，不再查库确认。若简报难度，区分slots中的请求档位与`actual_difficulty_counts`中的实际评级；例如“困难档训练，实际中等2题”，不能把hard槽内的mid题说成实际困难。失败：把 `message` 原样告诉用户。

需要核对父级配额或名称解析时，给正式命令加 `--plan-only`，检查返回的实际子点和题量后再去掉该参数生成。明确请求直接出题且目标清楚时不必额外询问确认。数量未指定难度时省略参数和槽内difficulty（解析为auto），自由安排常规基础与进阶题，按考官实际评级入库；不能擅自指定全mid。言语未指定难度也为auto，以练到指定知识点为主；easy/mid/hard仅作命题倾向，不因难度边界退题，不强求竞争错项数量或复杂题面。言语单题按两位审核较低评级记录，不虚标；命名保留请求档位，未指定为综合。政治、常识同样auto并按实际较低评级保存，难度仅作倾向；文字逻辑判断同样默认auto，难度只作倾向，独立核查答案唯一性和推理，不强制算式、固定步骤或复杂干扰；资料仍默认mid。用户明确指定比例时保留请求槽位与题量。数量口径不变：easy与mid严格区分，hard接受mid或hard、不接受easy；hard按两位审核较低评级保存。

### 2a. 脚本内部会怎么审（知道就行，不用你插手）

数量命题使用一次 `submit_questions` 结构化提交本组最终题目，不在正文混写多份 JSON 或改稿过程。10题仍按最多3题分组生成、审核后合并；格式错误按原文报告，不凭 `Extra data` 推断“十题超过上下文”或承诺拆五题就能解决，不截取第一份 JSON 绕过校验。

各模块共享目录、配额和入库。数量使用 `quiz_quantity.py` 的独立命题/复算要求，每次最多生成或审核3题，最后合并为用户请求的一批；题面与适用解法不受固定模板约束。数量考官不接收盲解步骤，避免被其错误解法引导。言语使用 quiz_verbal.py 的独立语境与选项比较要求，规则按题族切片（逻辑填空、语句表达、片段阅读）。一次请求 10 题仍是一批：填空每组最多 3 题，片段和语句每组最多 2 题，审核每组最多 3 题，合并为原请求批次。某一组生成或审核失败只重出该组，不要因此把 10 题拆成两次 5 题。言语选项没有大小或增减关系，脚本在审核前把正确项字母摊开到 A–D，解析里的「A项」「故选A」随字母一起改；已审过的题不再改字母。数量和资料的选项有顺序，不做这步。逻辑填空从词语学习词库抽一个指定词（`--plan-only` 的 `vocab_word`），正确项必须用上，题干不能写出该词。考官不接收盲解步骤，允许不同文体、问法和正确解法，不用固定关键词/句式否决；文字逻辑使用 quiz_reasoning.py 的独立语义检查，每次命题或审核最多3题，规则按题型族（演绎、论证、结构、日常结论）切片；考官不接收盲解步骤。演绎题（翻译推理、真假推理、组合排列）由命题人附 formal，`logic_model.py` 穷举判定答案唯一，判定不过当场退回；判定通过的题由考官核对 formal 忠实于题面，免去逐句断言核查，闸门入库前亲自重判。其余逻辑题原解析各句另由不带标答的独立断言核查验证，并核查明确设问及所有选项唯一性，防止答案正确却夹带错误理由或漏掉同构项。组合排列须用规范标签 `判断推理-逻辑判断-组合排列-单题`。出题、盲解、主审核、解析断言核查及修复统一只用 gemini-3.8-flash-high，不切换或回退其他模型。言语主审核核对整体解析；仅对程序摘取的用法限制断言另作核查，无此断言就省略该调用。额外核查使用原生结构化工具参数，每个断言一个必需字段；缺失或无效时停止，不能从正文补造审核。言语和文字逻辑题面、答案及考点已通过时，可先保留题面修解析一次，随后完整重审；仍不成立则允许重出。证据分别记录模型；政治、常识保持原文核验。

- **盲解官**：拿不到答案和解析，自己把题做一遍，报出它算出的选项，并逐个检查还有没有
  第二个选项也站得住。它的答案和题面键定答案不一致，或者发现第二个可成立选项，这题就退回。
  这条是「答案对不对、唯不唯一」的主判官——**不是**拿硬编码算式去套选项。
- **考官**：看得到答案和解析；数量重新复算，言语独立核对完整语境及所有选项，整体解析以准确、简洁、能说明本题择优依据为准，不要求穷尽词义或逐空讲解。对涉及用法限制的高风险原句另作不附标答字段的核查，必须覆盖摘取的全部断言，缺项不通过。允许说本题中不贴切，不要求错项任何语境下都错误。文字逻辑独立核对完整条件、推理方向、各选项和解析，不要求完整安排唯一，只要求答案唯一。检查考法、清晰度、解析正确性及用户要求。数量auto只评实际档位，不因评级不同拒绝正确题；easy/mid须符合对应档位，hard接受mid或hard但拒绝easy，实际评级不虚标。言语和文字逻辑只如实评档，难度不作为退题条件。跨题要求按整批检查。
- 盲解必须明确返回独立步骤、是否无解、其他可成立选项；字段缺失不得当作通过。两种审核是不同角色的独立调用，不是不同模型的能力认证。

**只有不合格的那几道会被退回重出，已通过的题原样保留**，最多 `--rounds` 轮（默认 3）。
补题只重出、重审未过关的题，已过关的题不重审；跨题要求（含 `brief`）在审核新题时对照整批现有题检查。
所以返回的 `rounds` 里出现多轮、`rejected` 里有题号，都是正常工作，不是故障。
全部通过后脚本自己签精简闸门收据并入库，你不要手跑 `generation_gate` 或 `import-batch`。

### 2a-plus. 考法变式轮转（数量、言语、文字逻辑、资料分析，脚本内置）

- 防止单知识点特训坍缩到一种默认考法：每个末级知识点在 `references/kaofa-variants.json` 里有 3–7 个考法变式（依据广东/国考真题与知识点页整理，按设问结构和解题动作区分，不按场景区分）。
- 特训时脚本给每道题分配一个变式，写进该题的出题要求（`declared_brief` 含“本题考法变式：xxx”），考官除按 `brief_ok` 核对外，还必须返回结构化的 `variant_match`：核对本题实际设问结构与解题动作是否属于该变式，`ok` 为 true 且给依据；退回最常见默认考法/只换场景会判不匹配而重出（DSH 与服务器链路均校验）。入库后记入 `data/kaofa-variant-ledger.jsonl`，下次优先分配近 30 天练得少的变式（出了还没做的题只算半次），最典型的默认考法自动降权。每日数量复习卷同一知识点最多 3 题。
- 变式分配按做题表现加权：入库时题号随变式记账，近 90 天各变式首次作答正确率换算成系数，错得多的变式优先且同批可占两份，稳定全对的少出，样本少时不调。三种用法，按用户说法选：
  - 只说“针对某知识点出 N 道”：不加参数，脚本自动铺开全部变式并偏向弱项。
  - “练我这个知识点最差的考法”“专攻薄弱考法”：`--focus weak`（蓝图槽位写 `"kaofa_focus":"weak"`），只在错得多的变式里出；还没有足够作答数据时自动退回全部变式，告诉用户原因。
  - 点名某个或某几个变式（“和定最值只练选票并列”）：先 `list` 或 `weak` 查到变式名称/id，再 `--variant '选票并列排名构造'`（多个用逗号，蓝图写 `"kaofa_variant":["vote-tie","..."]`）；考官照样逐题核对、照样记账。不要只写“只练XX”的 brief，那会跳过变式核对与记账。
  - 用户问“某知识点我哪个考法最差”：`python3 scripts/kaofa_variants.py weak '<知识点>'`，按正确率从低到高列出有作答数据的变式；`list` 也会给每个变式的 `accuracy`。
- **难度层级**：变式可标 `level`（1 入门 / 2 进阶 / 3 真题难点）。请求档位 easy 只挑层级 1，mid 挑 1–2，hard 挑 2–3（层级 3 加权优先），auto 不筛；没标层级的变式各档都可用，筛空时退回全部。数量、言语、判断推理、资料分析的全部变式已标层级（标注依据存于 `data/manual-kaofa-levels/`）。只有用户明确说出档位或配额（"简单/基础档""中等""困难/难题""三道困难"）才传 `--difficulty easy|mid|hard`（或槽位 `difficulty`），难度由考官的变式核对兑现；"贴近真题""广东省考难度""稍难一点""多点基础题"等倾向性说法仍按上文保留 auto，写进 brief，不切档；资料分析只在 easy/hard 时按层级筛，默认 mid 不变。新增变式时必须同时给 `--level`。言语、文字逻辑的评级仍不作退题门槛，靠层级挑变式来控难度。标层级用 `kaofa_variants.py edit '<知识点>' <id> --level N`（0 清除），新增时用 `add ... --level N`。
- 点名父知识点且题量少于子考点数时，优先分配近 120 天出题量少的子考点，不再固定从列表头开始。
- brief 明确锁定考法（如“只练允许相同的和定”“同构训练”“全部按某模型”）时，该槽位不分配变式，按 brief 出；“贴近真题”“稍难”等倾向性要求会与变式叠加，两者都要满足。用户只说“针对某知识点出N道”时不要另写 brief，脚本自动铺开变式。`--plan-only` 的输出里每题有 `kaofa_variant_name`，排计划时可直接告诉用户本批练哪些变式。
- 变式清单的维护只走下面的接口，禁止直接手改 JSON（接口会校验格式、查重并原子写入；知识点可写完整 tag 或节点标题，如“和定最值与数列构造”）：
  - 查看：`python3 scripts/kaofa_variants.py list '<知识点>'`，返回现有变式及近 30 天练习次数。用户问“某知识点有哪些考法”时用它回答。
  - 新增：`python3 scripts/kaofa_variants.py add '<知识点>' --name '≤16字' --ask '题干结构与解题动作，≤120字' --example '粤2025：真题片段' --weight 1-5 --id 英文小写连字符`。
  - 修改：`python3 scripts/kaofa_variants.py edit '<知识点>' <id> [--name/--ask/--example/--weight] [--typical]`；删除：`... remove '<知识点>' <id>`（典型考法不能直接删，每个知识点至少保留 3 个）。
- 用户说“这道真题的考法我们没覆盖，补进去”或“给某知识点补一个考法”时：先 `list` 对照现有变式，确认是新的解题动作或设问结构（场景、数字、难度不同不算）再 `add`；`--example` 只写用户给的或真题库里真实存在的题干，没有就留空，不得编造；返回 `高度相似` 时向用户说明最接近的现有变式，确认后才加 `--force`。新增后下一次特训会优先轮到它，告诉用户即可，不必立刻出题。
- 资料分析也用同一份清单和账本：10 个出题主标签（比重、比重差、增长率、增长量、基期量、平均、统计术语、混合增长、贡献率、比较）各有 4–10 个细分考法，每个标 `kind`（所属题型，对应整套轮转的 22 种题型）、可选 `types`（适用材料形态：text/table/monthly/years/two_series/pie/line）和 `need`（材料须提供的数据）。
  - 整套（`ziliao_agent_paper.py`）：由整卷蓝图调度器（`scripts/ziliao_blueprint.py`）一次锁定4篇材料形态、题材与20个槽位——题型按广东真题频率并只按已入库卷子轮转，细分考法近期少练/错得多优先，问法（题型+考法+选项形式）不重复，区间式每套1–2道、升降式0–1道、排序/个数/选主体等同一选项形式每套≤2道且每篇非精确选项≤1道，比重/增长率/增长量/基期量各至少1道，“是……的多少倍”问法每套≤2道，并预分配答案字母；综合分析和图表匹配不分配变式。`--plan-only` 打印蓝图及每题分配理由。
  - 专项（`ziliao_material_pipeline.py --tag`）：题型在该主标签对应的几种题型里轮转，细分考法近期少练/错得多优先并按材料形态过滤。用户只说“增长量出5题”时不写 brief，脚本自动铺开。点名某一个考法变式时走 `scripts/quiz_gm.py --variant`，本篇每题都核对该变式并记账；不要只用 `--brief` 写“只练某某”，那会跳过变式分配。
  - 入库后两条通道都记入 `data/kaofa-variant-ledger.jsonl`。
  - 整套默认按近 60 天做题表现加权（`scripts/ziliao_performance.py`，不用遗忘曲线）：错得多的题型和细分考法多出，稳定全对的少出，样本少时不调；`--no-adaptive` 关闭。每套的系数存在批次目录 `adaptive.json`。
  - 每日资料分析整套由 Hermes 定时任务在 04:40 自动出（07:40 补跑，仅前一次失败时重出），入口 `scripts/daily_ziliao_scheduler.py`；当天已入库或上一套一题没做会跳过。用户问“今天资料怎么没出/按什么出”时先看 `python3 scripts/daily_ziliao_scheduler.py --dry-run`。
  - 新增资料分析考法必须带 `--kind`，按需带 `--types`、`--need`：`python3 scripts/kaofa_variants.py add '资料分析-ABRX类-增长量计算与现期推算' --name '…' --ask '…' --example '粤2025：…' --kind growth_amount --types years,line --need '连续多期数值'`。`kind` 不合法或 `types` 写错会被拒绝。

### 2b. 要多个考法混在一批，就用 `--blueprint`

用户说「三种题型都要有」「难易结合」「3+3+4」这类**结构化要求**时，
不要退化成单标签，也不要连跑三次。改传蓝图（与 `--tag/--count` 互斥）：

```
terminal({
  command: "python3 /home/ubuntu/ExamSystem/scripts/quiz_lite.py --module '数量关系' --batch-id 'YYYYMMDD_hermes_最值阶梯_01' --blueprint '{\"slots\":[{\"tag\":\"数量关系-数学运算-最值问题\",\"count\":3,\"difficulty\":\"easy\"},{\"tag\":\"数量关系-数学运算-最值问题\",\"count\":3,\"difficulty\":\"mid\"},{\"tag\":\"数量关系-数学运算-最值问题\",\"count\":3,\"difficulty\":\"hard\"}]}'",
  workdir: "/home/ubuntu/ExamSystem",
  background: true,
  notify_on_complete: true
})
```

- `slots` 按顺序对应题号；每槽 `tag` 必填、`count` 必填、`difficulty` 选填（`easy`/`mid`/`hard`）。
- 每槽支持父级标签或 catalog 返回的精确子点；父级槽会继续按当前末级细分，子点槽锁定对应子树。指定某子点几题时从 catalog 复制其 tag，不照抄旧示例中的子点名。
- 题量总和仍限 1–15；所有槽必须同一模块；标签校验一视同仁，蓝图不放宽。
- 槽位是 Hermes 的编排自由度：**在用户指定范围内选考法、分配题量、用brief传达训练意图；用户未指定难度的数量槽保留auto，不自行加硬性难度配额。题面交由数量命题模型自由设计，不能在会话中绕过审核代写。**
- 太长可写文件再传 `--blueprint @/tmp/bp.json`。

### 2d. 申论（广东省考：县镇卷 / 省市卷）

用户报考县级，对应 2024 年起的「县镇卷」；省市卷也能出。申论题不进 AI 练题，单独在网页「申论」页作答：每题手写拍照上传，写完整套点「交卷」。交卷不评分；用户在 Hermes 点「申论复盘」选一份交卷发送后，按消息里 [SHENLUN_REVIEW] 的步骤先后台评分、再点评。

出题只调 `shenlun_quiz.py`（后台跑，整卷约 5–10 分钟，特训约 2–4 分钟）：

```
terminal({
  command: "python3 /home/ubuntu/ExamSystem/scripts/shenlun_quiz.py generate --batch-id 'YYYYMMDD_hermes_申论_01' --paper 县镇卷",
  workdir: "/home/ubuntu/ExamSystem",
  background: true,
  notify_on_complete: true
})
```

- 整卷：不给 `--types`，按 2024–2026 真题结构出 8 份材料、3 题（归纳概括 20 分 / 提出对策 30 分 / 文章写作 50 分）。`--paper 省市卷` 出省市卷。
- 题型特训：`--types`，可重复、最多 3 道。「练两道概括」就 `--types 归纳概括,归纳概括`，每道小题配一份两到四段的短材料；也可 `--types 提出对策`、`--types 文章写作`，综合分析、贯彻执行也能单练。复盘时只交了哪类题就按哪类题的标准评。
- `--theme` 指定主题（逗号分隔，如 `百千万工程,县域产业`）；不给就从近年真题常见主题里随机抽一个（主题池在脚本 THEME_POOL）。
- 材料是虚构的：案例地名人名用 A县、X镇、小王这类化名，宏观背景可用真实政策名。材料形式、篇幅、设问句式、要求措辞照 `references/shenlun-style.md`（由 8 套真题统计归纳，要调出题风格就改这个文件）。流程：命题蓝图 → 按蓝图并行写材料（程序核字数）→ 命题人出设问和要点表 → 审核官复核，不合格的题重写，最多 3 轮。失败把 `message` 原样告诉用户。
- 复盘：评分脚本 `shenlun_grade.py grade --submission <ID>` 写报告到 `data/practice-reviews/shenlun/`；点评按 `gd-gongkao-coach/references/shenlun-review-standard.md`（用户维护的评判标准）和 `solver-canon/08-shenlun.md` 写，分数只认报告，「两遍有分歧」的要点对照材料说明但不改分。
- 要点表和参考答案在用户交卷评分之后才显示，讲评前不要先把要点念给用户。

### 2c. 程序出图题（图形推理）

下面这些考点由 `figure_quiz.py` 出题：程序先生成题目结构，只从结构画图，独立判题器只看画出来的图重算答案，恰好一个选项成立才放行；解析也由判题事实生成。全程不调模型，一道题不到 1 秒。仍然只调 `quiz_lite.py`，它看到这些标签会自动转过去，参数照旧。

| 考点 `--tag` | 题型 |
|---|---|
| `判断推理-图形推理-空间类-六面体` | 展开图折纸盒（图案带方向） |
| `判断推理-图形推理-空间类-三视图` | 方块堆叠的三视图 |
| `判断推理-图形推理-空间类-立体拼接` | 两块拼成哪个（最不可能） |
| `判断推理-图形推理-空间类-立体旋转` | 旋转后是哪个 |
| `判断推理-图形推理-空间类-折纸剪纸` | 折叠剪切后展开 |
| `判断推理-图形推理-空间类-截面` | 过三点截正方体 |
| `判断推理-图形推理-特殊规律-平面拼接` | 平面碎片拼合 |

- 父级 `判断推理-图形推理-空间类` 或 `判断推理-图形推理` 会在其下题型间轮换；单批 1–15 题。
- 同一批只能全是程序出图题，不能和文字逻辑题混在一个蓝图里，要分两批。
- 这张表以外的图推细分（功能元素、图形间关系、其他样式规律等）和科学推理没有生成器，不要承诺出题。
- 排计划时，图推主力仍是粉笔真题；程序题用于点名的弱项加练和变式，计划里写明「系统程序出图」。

```
terminal({
  command: "python3 /home/ubuntu/ExamSystem/scripts/quiz_lite.py --module '判断推理' --tag '判断推理-图形推理-空间类' --count 5 --batch-id 'YYYYMMDD_hermes_空间类_01'",
  workdir: "/home/ubuntu/ExamSystem",
  background: true,
  notify_on_complete: true
})
```

**槽位还能带 `brief`，这是你对本批次的命题指令（自由文本，≤600 字）。**
脚本把登记定义与 `solver-canon` 的「固定识别 / 考场步骤 / 禁止」合并成批次快照，出题和审核共用，
`brief` 是在这个底座之上加你自己的要求——考情、侧重、要避开的退化写法：

```json
{"tag":"<catalog 返回的最不利原则子点 tag>","count":5,"difficulty":"hard",
 "brief":"必须出现残缺抽屉（某类数量不足 n-1）；至少 2 道用复合保证条件；禁止退化成和定排大小。"}
```

- `brief` **只能收紧，不能放宽**。想用它绕开闸门、豁免验算、放行低质量题，一律不行。
- 该写什么：本次侧重的子情形、要避开的退化写法、你联网了解到的新考情、用户临场提的难度要求。
- 不该写什么：题干原文、答案、具体数字——那是脚本的活。

|---|---|
| 一套 / 整套 / 20题 / 4篇 / 日练 / 广东省考默认 | `scripts/ziliao_agent_paper.py` |
| 一篇 / 5题 / 点名材料形态（柱图、表格、文字、饼图、折线） | `scripts/ziliao_material_pipeline.py` |
| 指定资料考点专项（5题=1篇，10题=2篇） | `scripts/ziliao_material_pipeline.py --tag` |
| 灵活出题：点名考法变式，或一篇里出 1–10 题（不必是 5/10） | `scripts/quiz_gm.py` |

两个入口共用同一条单篇流水线，每篇的步骤都由脚本完成，Hermes/DSH 不插手：

1. **蓝图**：整套由 `ziliao_blueprint.py` 一次锁定4篇材料形态、题材、20个槽位（题型、细分考法、选项形式）与答案字母；专项按考点轮转题型与考法。
2. **材料员**（一次模型请求）：只写正文、图表和分项；合计与舍入台账由程序从高精度底数独立舍入生成，保证数字自然、有真实舍入缺口。
3. **程序核对 + 材料审核**：材料硬检查不过直接带具体问题退回材料员；过了就一边做模型材料审核，一边并行出题。
4. **出题员**（每题一个请求，5题并行）：只写题干、解析和各选项的算式/错法；选项文字、精度、顺序（数值升序、区间从小到大、升降固定顺序）、答案字母和“X项：错误算式=结果”由程序生成。
5. **单题回修**：本地校验或审核只退回点名的题，回修请求只带该题、反馈和同篇题干摘要。
6. **篇内审核**：盲解、考官、整篇审核与视觉质检同时进行，通过后单篇签名；已通过且未改动的题、已查过的图不重审。
7. **整套**：4篇并发；整卷轻量闸门只核对每篇签名有效、内容与签发时一致、答案分布与整卷规则，然后带校验入库。单篇失败自动重跑一次。

### 整套（20题）

凡 20 题、4 篇、“一套/整套/均衡/日练”、广东省考/默认难度的资料分析请求，不论语音还是文字，一律用：

    cd /home/ubuntu/ExamSystem
    set -a
    . /home/ubuntu/ExamSystem/.env
    . /home/ubuntu/.hermes/.env
    set +a
    export PYTHONUNBUFFERED=1
    export EXAM_DB=/home/ubuntu/ExamSystem/data/exam.db
    python3 scripts/ziliao_agent_paper.py \
      --output-dir /home/ubuntu/ExamSystem/data/manual-ziliao-agent-paper \
      --db /home/ubuntu/ExamSystem/data/exam.db --import

- 必须后台执行（Hermes `terminal` background；DSH `pwsh` run_in_background），通常 4–8 分钟。不要再传 `--workers 2`（默认4篇并发）。
- **难度蓝图（只调难度，题型与配额锁定）**：“整套难一点/简单点”加 `--difficulty hard` 或 `easy`；按篇或按题调加 `--blueprint`，键为 `M01`–`M04` 或 `M03-Q4`，值为 easy/mid/hard，也可写 `{"difficulty":"hard","note":"用户原话里的命题倾向"}`：

      --blueprint '{"difficulty":"mid","slots":{"M02":"easy","M03-Q4":{"difficulty":"hard","note":"比重差贴近真题"}}}'

- 先加 `--plan-only`（不调模型）可打印整卷蓝图与每题分配理由，核对后去掉它正式运行。蓝图不能改题型、题量、综合问法或增删槽位。
- `--resume <批次目录>` 续跑：已签名的篇直接复用，只重做未通过的篇；沿用原难度，不能再传难度参数。
- 成功标准：退出码0、最后一行 JSON `passed=true`、`error` 为空且 `imported=20`。只报批次号与入库题数；失败原样报告脚本信息，不手写题、不手跑闸门、不降低标准放行。用户明确只验收不入库时去掉 `--import`。
- 用户提到经典计算加练时，整套仍出广东省考卷（经典计算加练轨暂不提供），并告知用户。

### 单篇或指定考点专项（5 或 10 题）

不指定考点，只出 1 篇 5 题（从整卷蓝图里取一篇；点名形态就取该形态）：

```bash
python3 /home/ubuntu/ExamSystem/scripts/ziliao_material_pipeline.py --import
python3 /home/ubuntu/ExamSystem/scripts/ziliao_material_pipeline.py --format chart --import   # 柱图/折线/饼图任选
```

指定考点专项：

```bash
python3 /home/ubuntu/ExamSystem/scripts/ziliao_material_pipeline.py \
  --tag '资料分析-ABRX类-增长量计算与现期推算' --count 10 --import
```

- `--tag` 只用资料分析出题主标签（比重、比重差、增长率、增长量、基期量、平均、统计术语、混合增长、贡献率、比较），不新造标签；不带 `--one-paper` 时题量只能 5（1篇）或 10（2篇，两篇并行后合成一批入库）。
- 灵活出题（Hermes 与 DSH 同一条命令，DSH 的技能目录链到本文件）：`python3 scripts/quiz_gm.py --module '资料分析|数量关系|言语理解|逻辑判断' --point '<知识点简称>' --variant '<考法变式，可省略>' --count <题量> --actor hermes|dsh`。省略 `--variant` 时在该知识点已登记的变式里自行分配（少练、错得多的优先）。写了 `--variant` 则这批只出该变式。资料是一篇材料、1–10 题，指定变式后整篇都是它；读数、文字理解默认用文字材料。文字题 Hermes 用 `--actor hermes` 调 `quiz_lite` 写完（1–15 题）；DSH 用 `--actor dsh` 只取槽位，再按 `agent-mode.md` 自己写题。先 `--plan-only` 核对，要入库再加 `--import`。图形推理、科学推理、定义判断、类比推理不走这条。
- `--format`：text / table / monthly / years / two_series / pie / line，或 chart / 柱图 / 折线 / 饼图 / 表格 / 文字。
- `--brief '<用户原话>'`：用户对考法的额外要求原话传入（如“只练现期求增长量”）；锁定式要求会让脚本不再分配别的变式。
- `--difficulty easy|mid|hard`：只有用户明确指定档位才传，默认 mid。
- `--batch-id` 按命名规则传 `YYYYMMDD_<hermes|dsh>_<考点>_<两位序号>`；`--plan-only` 只打印各篇题型与考法，不调模型。
- 用户要 6–9、11–19 题时，说明只提供单篇5题、专项10题或整套20题，请用户选择。经典计算加练（轨B）暂不提供，告知用户并按粤考日练出。
- 后台执行，通常 2–4 分钟（10题约 3–5 分钟）。成功须退出码0、最后 JSON `passed=true` 且 `imported>0`；只报批次号和入库题数。

## 政治理论、常识应用：先核验原文再出题

执行口径见 `references/politics-common-workflow.md`。这两个模块复用 quiz_lite，强制权威原文快照、独立逐项核验。不要调旧 quiz_generator 绕过原文检查。DSH 写题时同样先按本节备好原文资料，再按 `references/agent-mode.md` 出题，审核须核对每个选项的原文出处。

```bash
# 只点模块时：政治默认10题、常识默认5题；也可传count、tag或blueprint
python3 /home/ubuntu/ExamSystem/scripts/quiz_lite.py --module '政治理论' --batch-id 'YYYYMMDD_hermes_政治理论_01'
python3 /home/ubuntu/ExamSystem/scripts/quiz_lite.py --module '常识判断' --count 5 --batch-id 'YYYYMMDD_hermes_常识_01'
python3 /home/ubuntu/ExamSystem/scripts/quiz_lite.py --module '政治理论' --tag '政治理论-时事政治-重要文件' --count 3 --question-type multi --sources gd-science-literacy-2026 --batch-id 'YYYYMMDD_hermes_科学素质多选_01'
```

- 先读取 `policy_sources.py status`，按用户需求选对应原文；资料少时先用联网检索找到原发机关正文，再 `policy_sources.py add @资料登记.json`，由程序自己获取正文。不能自己编写资料正文或搜索摘要充当原文。
- 自动资料候选在 `data/manual-policy-sources/candidates.json`。候选未核验，不能直接出题；每周第一次政治/常识出题前梳理候选，新热点相关才登记，不把所有新闻塞进练习。
- 蓝图可逐槽传 `question_type: judge/single/multi`；政治整模块默认4判断+4单选+2多选，这是2025/2026回忆版训练结构，不是2027官方承诺。专项可自由指定题型与比例。
- `--sources id1,id2` 选择1–8份资料；`--as-of YYYY-MM-DD` 限制资料发布日期；新题默认今天。时政主攻近一年重要内容，但基础理论和仍适用的重要文件不过期删除。
- 默认模块蓝图只是启动组合，Hermes根据真题分布、学习证据和用户要求重新编排；不要长期只刷初始种子资料。
- 新知识点可讨论后登记；政策文件是证据，不是每篇都新造知识点。资料分析和其他模块原有入口不变。

## 科学素质文件对其他模块的影响

2026-09-23公布的广东科学素质方案作为选材依据，未宣布2027题量变化。
言语可用科普、科技伦理、AI应用的原创材料，但答案必须从文段推出，不把政策记忆当阅读能力；
逻辑可用科技实验、证据与因果场景，不依赖题干未提供的专业常识；
数量可采用科技产业情境但锁定用户指定数学考法；资料分析可用产业/研发/能源模拟统计，仍要求数据自洽与程序图表。
不得把所有练习强行换成AI主题，不提高未授权题量与难度，不据推测增开科学推理图题。

## 流程通用性参考

DSH 写题的操作步骤见 `references/agent-mode.md`。该链路（生成 → 审核 → 预检 → 闸门入库）的已落地项与剩余缺口见 `references/dsh-generality-gaps.md`：断言清单（`--dsh-claims`）、全量预检（`--dsh-check`）、失败重导不占 batch_id、演绎题 formal 唯一解穷举已落地；review.json 自动组装、变式漂移检测待做。

- **出题 agent 的角色**：只做出题本职（第 0 节 Track A），**绝不改代码**（铁律 6）。缺陷一律按该文档第 2 节 backlog 登记，由维护轨落地；出题会话不得 patch 脚本。
- **缺陷未修完前**：命中缺口时按该文档第 4 节「临时工作方式」在不动代码的前提下跑完当前批，再登记 backlog。
- **改进者**：按该文档第 2 节 backlog 落地，目标是让出题人只做出题本职、不介入流程自修复、不碰代码（验收北星见第 5 节）。

## 禁止

- 为找入口无目标翻长参考、自己拼题目草稿、自己跑闸门；本技能明确要求的原文与工作流资料须按需读取
- Hermes 出题失败后自己写题顶上（DSH 按预检报错修被点名的题属于正常流程）
- 把日练 图形5+逻辑15 套进专项小卷
- 没听清录音就改出快照里的「下一步候选」
- **出题会话里改任何代码**（`scripts/**`、`server/**`、`src/**` 等），或为过闸门手工改写证据结构 / 手填对齐格式。流程缺口按 `references/dsh-generality-gaps.md` 第 2 节 backlog 登记，交由维护轨落地，出题 agent 只做出题本职。
